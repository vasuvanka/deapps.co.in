HUMAN-CENTRIC COGNITIVE MODEL

Four Modes. Zero Autonomous Surprises.

Most "AI phones" act like unpredictable chatbots that hallucinate or execute background actions without permission. deLauncher implements a strict four-mode policy where the user is always in sovereign control.

Mode Behavior Product Policy
Ask Responds to explicit requests and natural language commands. Always available through search.
Suggest Offers relevant, timely contextual suggestions (e.g. low battery, upcoming meeting). Opt-in context, rate-limited, explainable, dismissible.
Assist Prepares actions for user confirmation (e.g. prepares dialer or draft). Mandatory user confirmation for all consequential actions.
Automate Runs explicitly configured user routines. Disabled until configured; never runs silently.
AssistantPolicy.kt Deterministic 
sealed interface ActionResult {
    data class Success(val message: String) : ActionResult
    data class RequiresConfirmation(
        val description: String,
        val actionId: String
    ) : ActionResult
    data class RequiresPermission(val permission: String) : ActionResult
    data class NeedsClarification(val question: String) : ActionResult
    data class Failure(val reason: String) : ActionResult
}
The model never calls Android APIs directly. It returns structured intent schemas that pass through strict policy verification.
SMALL ON-DEVICE MODEL INFERENCE

FunctionGemma 270M & LiteRT-LM.

Instead of sending your personal requests to expensive, privacy-invasive cloud LLMs, deLauncher utilizes an optimized FunctionGemma 270M model running locally on-device via the LiteRT-LM runtime.

⚡
Sub-Second Local Intent Classification Extracts intent and parameters (e.g. `CALL_CONTACT`, `contact_name: "Arun"`) in under 1 second without network connectivity.
🛡️
Air-Gapped Privacy Voice and text queries are processed entirely within the app sandbox. No queries are uploaded or logged to external servers.
🔄
Deterministic Fallback Pipeline If the model is loading or the hardware is constrained, the engine falls back to regex matching and deterministic search providers.
IntentContract.json v1.0 Schema 
{
  "schema_version": "1.0",
  "intent": "CALL_CONTACT",
  "parameters": {
    "contact_name": "Arun"
  },
  "confidence": 0.94,
  "requires_clarification": false
}
Confidence scores serve as validation signals and never bypass permission checks or confirmation rules.
DETERMINISTIC KOTLIN EXECUTION ENGINE

Controlled Action Registry.

The model is mathematically prevented from executing arbitrary code. Every mobile capability is defined in a typed Action Registry with parameter schemas, capability status, and Android permission boundaries.

🔒
Zero Code Generation / Execution No `eval()`, no dynamic bytecode loading, and no raw shell commands. All actions are compiled native Kotlin handlers.
📋
Capability Allowlist Catalogued across 17 distinct domains (Apps, Contacts, Settings, Audio, Files, Alarms, Maps) with clear capability status.
✋
Safe Platform Fallback When an action cannot be run directly due to Android security boundaries (e.g. airplane mode), deLauncher safely redirects to system settings.
ActionRegistry.kt Allowlist 
interface ActionExecutor {
    suspend fun execute(request: ActionRequest): ActionResult
}

enum class CapabilityStatus {
    AVAILABLE,
    PERMISSION_REQUIRED,
    SETTINGS_REDIRECT,
    APP_REQUIRED,
    SYSTEM_RESTRICTED
}
The model suggests intents; the Kotlin Action Registry determines whether the action is permitted by Android and the user.
SOVEREIGN DATA PERSISTENCE

Local Room SQLite & Ephemeral Context.

deLauncher separates transient real-time context from permanent memory. Your personal preferences, routines, and search history reside exclusively in encrypted local Room SQLite databases on your physical storage.

📦
No Silent Memory Formation Personal memories (e.g. routines, preferred apps, default contacts) are explicitly approved by the user, never harvested covertly.
🗑️
Inspectable, Editable & Clearable View exactly what the assistant knows about your preferences. Clear short-term context or wipe all memory with a single tap.
⏱️
Transient Event-Driven Context Context snapshots (battery level, schedule, mode) have strict TTL expiration and are discarded after evaluation.
ContextSnapshot.kt Room DB 
data class ContextSnapshot(
    val timestamp: Long,
    val timeContext: TimeContext?,
    val deviceContext: DeviceContext?,
    val scheduleContext: ScheduleContext?,
    val preferenceContext: PreferenceContext?
) // Stored strictly on-device
Raw contacts, messages, and call logs are queried securely through Android providers on-demand and never cloned into permanent databases.
The Sovereign Data Charter

Taking privacy seriously:
A mathematical guarantee.

0-Telemetry Audited

Big tech companies define "privacy" as promising not to sell your data to third parties—while using it themselves to train models and serve targeted ads. We believe privacy must be structural: if we never collect your data in the first place, it can never be leaked, subpoenaed, or exploited.

01

Zero Outbound Telemetry

Zero analytics SDKs (no Firebase, no Mixpanel, no Facebook SDK, no crashlytics collectors). Inspect our Android manifests and network traffic with Wireshark: 0 outbound packets.

02

Progressive Permission Model

We never badger you with an all-or-nothing permission checklist during install. Contacts, calendar, and storage access are requested only when you trigger a specific search or action.

03

Sovereign Local Memory

Your interaction history, search cache, and assistant preferences live exclusively in local Room SQLite storage. You can inspect, modify, export, or delete any record with one click.

04

Air-Gapped by Architecture

Every tool in deSuite operates 100% offline. Turn on Airplane Mode: deLauncher searches apps and contacts, OpenPause gatekeeps, and deMusic plays lossless FLAC with zero degradation.

deApps & deSuite Sovereign Data Charter

1. Absolute Zero Telemetry: None of our applications (deLauncher, OpenPause, deMusic, deVault) embed tracking SDKs, behavioral analytics, Firebase analytics, crash dump aggregators, or telemetry reporting tools.

2. On-Device AI Privacy: Natural language intent recognition uses on-device models (FunctionGemma 270M). All voice and text queries remain within your device sandbox.

3. Local-First SQLite Persistence: Your app usage stats, impulse wins history, search queries, and assistant memory records are stored entirely in local on-device SQLite databases (Room). Your data never touches an external server.

4. Progressive Permissions:
• OpenPause: Requires Accessibility & Usage Stats solely to detect when configured addictive apps are launched on your local phone.
• deLauncher: Requires Default Home / Launcher permissions to display your home screen and dock; contacts/calendar permissions are requested only on-demand when searched.

5. Verification: Our network manifests contain zero hidden background network communication endpoints. You can audit or monitor with any network proxy tool.
